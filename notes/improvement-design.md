# Substantial improvement design

## Scope and fixed decisions

Implement only tasks **5–8, 12–17, 19–20, 24–25** from `notes/improvement-tasks.md`. Tasks 5, 8 and 20 literally stop at ellipses; this design covers their stated intent, not imagined continuation. No account/password product, synchronization, general copy-management framework, tag administration, or recovery browser is added. Tasks 1–4, 9–11, 18 and 21–23 belong elsewhere. Consuming shared controls is allowed; redesigning those other features is not part of this work.

Observed baseline: Svelte 5.38/TypeScript/Vite, FastAPI 0.141, Pydantic AI 2.40, SurrealDB ORM 0.33.1. The frontend has no router/store/component library dependency beyond Svelte. `App.svelte` routes via History API; `api.ts` supplies session/CSRF; `local.ts` prefixes keys with `notebook:`. `recipes.py:139` already paginates summaries, `recipes.py:415` requires identity for organization, and `ingredients.py` parses quantities/converts mass but does not parse ingredient lines. `schemas.py:20` retains ingredient IDs, original text and string quantities. `repository.py:206` owns real atomic transactions; do not replace its compatibility layer. `admin.py:133` transfers ownership without a client revision and needs correction. Existing category arrays incorrectly mix meals with cuisines.

### Invariants

- Preserve recipe/group/ingredient legacy IDs, original source and authored description/directions/notes/unclassified/modifications. Never silently rewrite old recipes or replace prose with model output. Existing display-only separator behavior is not permission to paraphrase.
- All recipe writes still require an active named profile; organization and local drafts do not. Display names are labels, not credentials: entering an existing name creates a different user, never logs into that user.
- Admin derives from a live device credential and active user permission. Every privileged mutation re-resolves authorization inside its repository transaction. UI visibility and cached session booleans are not authorization.
- Keep pending/hidden/deleted photos and private profile fields out of public summaries, tags, settings and saved lookups, including for admin callers. Public recipe projections require status=published and no deleted_at; existing `_live`/`_project` only exclude hidden/deleted and must not expose any server draft rows. Keep existing detail/photo authorization behavior; adding draft visibility is not part of this work.
- API changes have explicit DTOs/response models and regenerated `api.generated.ts`; quantities remain strings in existing recipe contracts. Do not hand-edit generated types.

## 1. Wire contracts (all paths below include `/api`)

Errors retain the existing `{detail: string, error: {code: string, message: string}}` envelope. Use 401 for absent/unusable identity, 403 for active non-admin/non-owner, 404 for unavailable resources, 409 for stale revisions, 422 for validation, 429 for budget exhaustion, 503 for unavailable organization. Mutations, private lookups and admin responses are `no-store`. Keep Origin and CSRF enforcement on every POST, including anonymous parse and saved lookup; bootstrap CSRF using existing `GET /api/session` without creating a profile.

### Identity/admin (5–7)

- Retain `GET /api/session -> Session {user: User|null, device_id: string|null, admin: boolean, csrf_token: string}` and existing identity POST/PATCH/device/pairing routes. `User` retains current public fields; expose admin only through `Session.admin` for the current user, not a new public role-directory field. Add named response DTOs `SessionResponse` and `PublicUser` without changing these wire shapes.
- Persist `User.is_admin: bool = false` as a schema field. `resolve_context(request, repo)` sets `context.admin = bool(context.user and context.user.is_admin)` after live device and canonical-user resolution. Remove admin-session authority. `authorize(..., admin=True)` requires a user, checks its flag, touches device/user for transaction conflict fencing just as user authorization does, and records user actor identity.
- `POST /api/admin/login` is removed (404); an old admin cookie grants nothing. Remove the separate admin logout UI/route. Profile logout is existing `DELETE /api/devices/{session.device_id}`; after success call `session(true)`. Warn in a shared confirmation modal that this browser loses access if no other device exists; do not delete its local drafts/bookmarks. No new logout recovery/login mechanism is implied.
- Extend `GET /api/admin/users?q=&start=0&limit=20&eligible_owner=true -> {users: PublicUser[], items: PublicUser[], total: number, start: number, limit: number, has_more: boolean}`. `eligible_owner` defaults false to preserve admin user management; true filters active, unmerged users **before** search/pagination. Case-insensitive name/ID substring search, deterministic `(display_name.casefold(), id)` order. Max q=100 and existing max limit=500. Only admins can query; return allowlisted fields, no device hashes, tokens, payloads or credentials. Duplicate names are disambiguated by a short ID label in the UI; selected values are full IDs.
- Retain `POST /api/admin/recipes/{recipe_id}/owner`, require `OwnerInput {owner_id: string|null, expected_revision: integer>=1}`, return `OwnerResult {id: string, owner_id: string|null, author_name: string|null, revision: number}`. Author selection is ownership transfer, not a free-text byline. Normal UI selects an active user, not null; retain explicit null API capability for existing administrative callers. Reject a submitted blocked/merged target with 422 rather than silently selecting a different person. Missing/non-live recipe returns 404. Compare expected revision, use `recipes._save_revision` (including its revision-1 protection), user/recipe fencing and audit in one transaction; invalidate catalog after commit. A 409 never retries using a newer client revision. The component refetches detail after success so permissions and ETags update. Historical recipe prose/IDs/photos stay unchanged.
- Remove the entire opaque recipe-ID ownership/recovery tab from `Admin.svelte`. Keep protected revision/restore endpoints operational for existing callers; do not invent a deleted-recipe browser. Admin restore must also use `_save_revision` and classifier validation before commit. On a live recipe's byline show **Change author**, opening the searchable selector. No owner-edit fields in ordinary recipe create/update.

### Configurable neutral copy (8)

| field | default | maximum | consumer |
| --- | --- | --- | --- |
| `site_title` | `Recipes` | 80 | header brand |
| `site_tagline` | `Share your food.` | 160 | header subtitle |
| `home_title` | `Recipes` | 120 | unfiltered browse heading |
| `home_intro` | empty string | 300 | browse intro, omitted when empty |
| `footer_text` | empty string | 200 | footer, omitted when empty |

- `GET /api/site-settings -> SiteSettings {revision: number, copy: SiteCopy}` is public, public/no-cache with ETag. Missing settings returns defaults at revision 0 without writing at startup/read time.
- `PUT /api/admin/site-settings` takes `SiteSettingsUpdate {expected_revision: number>=0, copy: SiteCopy}` and returns `SiteSettings`. All five fields required; unknown keys forbidden. Titles must be nonblank; optional copy may be empty. Reject control characters except normal whitespace; enforce field limits server-side. Display as Svelte-escaped text, never HTML/Markdown. Do not trim or modify recipe prose as part of copy changes.
- Store singleton `site_settings:public` with `revision` and `copy`; first write at expected 0 atomically creates revision 1, later writes CAS. Audit previous/new allowlisted copy in the same transaction. Parallel initial creates/stale edits return 409. No secrets/configuration keys appear in this DTO.
- Admin adds **Site text** tab with labeled fields, default/reset preview and Save. Reset populates the form with defaults; only Save persists. Keep dirty inputs on failure/conflict; explicit reload discards them. Save refreshes the shell's copy state. Public fetch failure renders neutral defaults and a retryable non-blocking notice, not a blank page. Selected/search/saved headings are functional fixed labels, not configurable marketing slots.

### Tags, classifiers and search (12–15)

- Hard-coded, ordered `MEAL_CLASSIFIERS = ("breakfast", "lunch", "dinner", "dessert")`. American/asian/indian/mexican remain ordinary tags and cease being category sections. No further meal names are inferred. A recipe may have zero or one classifier and any number of ordinary tags within existing limits.
- Define backend `tag_key(value: str) -> str` as stripped, Unicode NFC-normalized, casefolded text. Matching/classifier validation/deduplication use this key. For **newly submitted tags**, strip/NFC normalize, drop duplicate keys retaining first spelling, canonicalize classifier spelling to lowercase, then enforce max 50 tags/max 80 characters and reject blanks. Ordinary existing tag spellings in stored recipes are not rewritten by a migration. `/tags` deduplicates equivalent spellings with deterministic first spelling (sort by key, then raw spelling); autocomplete reuses that spelling. Do not collapse hyphens, spaces or accents or introduce fuzzy automatic merges.
- `GET /api/tags -> TagCatalog {tags: string[], classifier_tags: string[]}` keeps `tags` and adds the canonical classifier array. Collection comes only from public live recipes. Creating a tag means explicitly selecting **Create “…”** in the editor and submitting it with the recipe, not a tag-write endpoint. No creation on blur/comma.
- Validate classifiers in recipe create/update and administrative restore before any recipe/revision/job write; `422`, message **Choose only one meal type: breakfast, lunch, dinner or dessert.** Keep validation on write inputs, not `Recipe` output, so legacy multi-classifier recipes remain readable. On edit show the conflict and require the author to resolve it before saving. Do not auto-retag import history or restore records silently.
- Browsing assigns each recipe to exactly one group using the first matching classifier in canonical order, otherwise **Other**. This read-time rule also deduplicates pre-existing multi-classifier data without altering it. Unfiltered home retains sections; active filters/search can use one Results group, not a permanent replacement of home sections.
- Extend `GET /api/recipes?q=&tag=<repeatable>&owner_id=&offset=0&limit=60`. New `tag` accepts at most 50 values, each 1–80 chars. Existing summary response shape stays `{items, offset, limit, total, has_more, errors, groups}`; give it named `RecipeListResponse`/`RecipeSummary` DTOs. Apply selected `tag` filters with **AND**, then text matching and owner filter, before pagination. Unknown explicit tags match nothing and produce an `errors` warning rather than accidentally exposing all recipes.
- Preserve existing optional `q` advanced-parser semantics for legacy links: current `tag:x`/`-tag:x` tokens form the existing OR tag clause (`-tag` is not silently reinterpreted as exclusion in this task). New explicit selected tags AND with that clause and free text. Casefold tag comparisons. Existing unknown-field/tag warnings remain. Do not expand the search language here.
- Browser URLs: `/?q=soup&tag=dinner&tag=vegetarian`, `/saved?q=soup&tag=dinner`; `q` may be absent. Header search updates only `q` while preserving repeated tags and `/saved` vs `/`; tag add/remove updates only tags and preserves q. Back/forward restores both. Legacy hash translation remains supported without ID rewrites. New links use repeated `tag`, not injected advanced syntax.
- Home displays at most the first six sorted tags in one nonwrapping, width-clipped row, reserving visible space for **Search tags**. The search control is always visible and opens a live-filtered shared picker over the complete catalog. Hidden quick chips must not remain focusable; narrow screens may expose fewer than six. Selected tags live in a separate removable-chip region and are not hidden by that row. Keyboard selection, selected states, clear-one/clear-all, no-results and search-error states are required.

### Anonymous organize + ingredient lines (16–17, 20)

Keep `POST /api/parse {source_text: string}` (existing max 100,000 characters) returning named `ParseResult` with existing `source_hash`, echoed exact `source_text`, description, ingredient_groups, directions, notes, unclassified and warnings. Drop `require_user` for this read/transform operation **only**. Do not create anonymous user/device records. Use live context when available; recognized revoked/blocked credentials must not become a way to bypass a block (403); an unrecognized/expired browser may use the anonymous budget. For quota reservation: anonymous gets trusted-IP + global scopes; named gets user + trusted-IP + global. Use the existing atomic quota service, `client_ip`, body/Origin/CSRF guards, timeout and shared concurrency semaphore. Never trust forwarded headers. Reserve before provider work, outside the external call's transaction; do not refund failures. No provider keys or full authored input in logs/errors. Whole-recipe span classifier keeps its existing maximum two provider requests (initial + one validation retry), budgeted as two.

Add **separate ingredient preview** so editing lines never silently invokes an LLM on each keystroke:

- `POST /api/ingredients/parse` body `IngredientLinesRequest {lines: IngredientLineInput[]}`; `IngredientLineInput {id: string, text: string}`. IDs obey existing ingredient identifier limits, unique per request; 1–1000 lines; each nonblank text <=10,000 characters, total text <=100,000 and existing 150 KiB HTTP cap. Echo IDs/order/text byte-for-byte; never generate replacement IDs. This endpoint is anonymous-capable under the same credential/CSRF/IP rules.
- Response `IngredientLinesResult {items: IngredientLineResult[], warnings: string[]}`; each `IngredientLineResult {id: string, text: string, method: "deterministic"|"llm"|"unparsed", ingredient: IngredientOutput}`. `ingredient.id === id`, `ingredient.original_text === text`, `grams === null`. Reuse existing `IngredientOutput`: `quantity`/`quantity_max` numeric-valued strings or null, `unit`, `name`, `preparation`, `optional`. This is the simple number/unit/ingredient view; ranges and old metadata remain compatible internally, not separate editing inputs. No new required fields in recipe create/update.
- Backend functions: `parse_ingredient_line(text: str) -> dict | None` in `ingredients.py` (pure, no IO; None means uncertain), and `parse_ingredient_lines(lines, settings, *, reserve_fallback) -> IngredientLinesResult` in new `ingredient_lines.py` (orchestrates deterministic parse and at most one batch fallback). `reserve_fallback` is an async callback from the route which commits `consume_ai_quota(..., units=1)` immediately before external fallback. Pure all-deterministic requests consume no AI quota; rate-limit this endpoint to 60 requests/5 minutes per trusted IP using existing durable limiter.
- Deterministic grammar: leading integer/decimal/fraction/mixed or Unicode fraction via `parse_quantity`, optional ordered range (`1–2`, `1 to 2`), optional known unit, nonempty remainder as exact ingredient name/preparation slices. Accept attached recognized units (`250g flour`), unitless counts (`2 eggs`), comma preparation (`1 onion, chopped`), explicit trailing `(optional)`, and quantity-free plain names (`salt`) or `salt to taste` with null amounts. Normalize known unit aliases to `g`, `kg`, `mg`, `oz`, `lb`, `ml`, `l`, `tsp`, `tbsp`, `cup`; no inferred conversions/density/grams in this parser. Negative/nonfinite/zero-denominator/reversed or oversized quantities, package arithmetic (`2 x 400 g cans`), multiple incompatible measures, unknown unit-like abbreviations and ambiguous parenthetical measures are uncertain, not guesses. Round-tripping retains original text regardless of derived fields.
- Collect **all** uncertain rows, then invoke `ai.parse_ingredient_lines_batch(lines, settings)` exactly once, only with their IDs/text (no recipe prose/user metadata). One model request, `retries=0`, `UsageLimits(request_limit=1)`, provider transport retries disabled for this call. No row-by-row requests and no second repair call. A structured fallback output identifies original ID and source spans for amount/range/unit/name/preparation/optional marker, or explicitly unparsed; materialize source slices server-side, normalize only recognized numeric/unit tokens. Validate exact ID coverage (no duplicate/foreign IDs), in-bounds nonoverlapping spans, amounts via existing bounds, exact source-derived name/preparation and original text. Invalid batch shape rejects the batch's inferred values; invalid individual row remains unparsed. Never accept model-authored recipe text, grams or instructions. Prompt-injected ingredient text is data.
- Fallback timeout/provider/validation failure returns 200 with deterministic successes and remaining `method:"unparsed"`, warning `ingredient_fallback_unavailable` or `ingredient_fallback_invalid`. Unparsed ingredients retain exact original text with null quantities, empty name/unit/preparation, optional false; thus normal display falls back to original text without misleading scaling. Quota failure returns 429 before calling the provider; editor retains all input and can explicitly save uncertain rows as original text. Blank/oversized/duplicate IDs are 422, not provider work. Whole-recipe `/parse` still returns 503 on classifier outage.
- Whole-recipe Organize first calls `/parse`; after guarded application, the editor calls `/ingredients/parse` once for its returned ingredient rows. The first call classifies authored prose; the second deterministically interprets ingredient lines with at most one batched fallback. A second-call failure must not discard the valid classified source/groups; mark quantities unresolved and allow review/text-only publication. Organization is not claimed to be one total provider request: the **ingredient fallback** is one batch.
- Edits to organized ingredients use one input per row, Enter inserts/focuses the next stable-ID row (ignore IME composition), remove/reorder remains possible; optional groups remain. Display original_text when present, otherwise existing formatter; **unchanged legacy rows retain all existing fields**. A changed line immediately clears its derived amounts/grams and enters a dirty-line set. **Organize ingredients** explicitly previews all dirty lines together; Publish/Save performs the same batch once for still-dirty lines before submitting. Keep text unchanged and reviewable; parsed numeric data must not be used after further typing. For unavailable parsing, offer explicit **Save with original ingredient text**; never silently retry AI in a publish loop. Empty UI placeholder rows are omitted; intentionally entered nonblank text is not dropped.
- Guard both async stages using ID+text snapshot and `ParseGuard` generation/AbortSignal. Ignore late results after typing/reorder/delete/undo/navigation/new draft. Save captures one snapshot and disables edits while preparing/submitting; cancel leaves local draft intact. Server saves still validate all fields and ignore client grams/authority, enqueue enrichment atomically, require identity and retain expected_revision/idempotency.

### Saved recipe retrieval (25)

Bookmarks remain on this device (`notebook:bookmarks`, string array); this task adds retrieval, not synchronization/accounts.

- `POST /api/recipes/lookup` body `RecipeLookupRequest {ids: string[], q?: string, tags?: string[]}` (0–100 IDs, existing recipe ID grammar allowing optional `recipes:` prefix; q defaults empty, tags defaults [], same limits/semantics as list q/repeated tag); response `RecipeLookupResponse {items: RecipeSummary[], unavailable_ids: string[]}`. Define this static route before `/{recipe_id}`. Deduplicate normalized IDs preserving first request order; return public live published summaries in that order, filtered by q/tags using the shared list search predicate. Compute unavailable IDs before applying q/tags, so a filtered-out bookmark is never labeled missing. Unavailable includes missing, unpublished, hidden and deleted identically, even for admin; expose no reason or tombstone details. IDs are normalized to existing bare wire IDs; do not remap/hash legacy IDs. No detail/ingredient/photo loading and no N+1 GET loop. Use a bounded parameterized ID-filtered projection, public visibility conditions, approved thumbnails only; do not use a stale catalog to resurrect a deleted bookmark. `Cache-Control: no-store` avoids shared caching of personal selection. Read-only POST keeps CSRF policy and creates no server bookmark state.
- `/saved` loads **all** validated local bookmarks in batches of 100 (at most two concurrent requests), independently of homepage pagination. Dedup and preserve local selection; malformed local entries are reported locally without sending invalid IDs. Progress appears until every batch succeeds/fails; no premature empty state. Failed batches expose retry and retain successful results. Missing recipes show a neutral unavailable count and explicit remove-unavailable action; never erase bookmarks on transient failure.
- Send active q/tags with every lookup batch; server applies shared list search semantics within the requested-ID candidates, including description/directions matching, without asking the browser to download the collection. On filter changes abort/ignore the old batch generation and refetch all bookmark chunks with new filters; optionally reuse a complete unfiltered result for clearing filters. Never paginate `/recipes` to discover saved recipes, nor approximate full-text search from truncated summaries. Render a Saved recipes heading and one result grid; no Load more dependency. React to local bookmark `storage` changes and entering the route.

### Editor-owned exports and draft format (24)

- `Editor.svelte {recipeId?: string; draftId?: string; navigate: (path:string, options?:{replace?:boolean})=>void}`. New recipes always start `blank('text')`; ignore old `editor-mode` preference for new work (leave recovered draft mode intact). Main textarea label **Paste or write your recipe**, action **Organize**, secondary organized view **Edit as text** and **Undo organization**. Switching back must not overwrite retained source with formatted text silently: offer original text or explicitly chosen formatted current structure, and keep undo/original source in local draft. Do not expose Text/Structured as primary format choices.
- Name prompt is always visible at bottom near submit while session lacks an active user, outside a busy/disabled parent fieldset. Submit disabled for missing identity, pending load/parse/publish, invalid title/classifier or unresolved permission. A focusable tooltip wrapper explains **Set your name to publish** (or **Set your name to save changes**); also associate inline help via aria-describedby since disabled buttons do not receive keyboard focus. Keep Publish handler's auth guard for programmatic submissions and expired sessions. Anonymous Organize remains enabled.
- `drafts.ts` owns browser persistence. Export `DraftSummary {id:string; name:string; updatedAt:string}`, `LocalDraft {version:2; id:string; name:string; updatedAt:string; draft:RecipeDraft; publishKey:string; undo?:RecipeDraft; ingredientLines?:Record<string,string>}`, `listDrafts(): DraftSummary[]`, `readDraft(id:string): LocalDraft|null`, `createDraft(name?:string): LocalDraft`, `saveDraft(value:LocalDraft): boolean`, `renameDraft(id:string,name:string): boolean`, `deleteDraft(id:string): boolean`, `draftHref(id:string): string`, `subscribeDrafts(listener:()=>void): ()=>void`, `migrateLegacyDraft(): boolean`. `createDraft` returns an in-memory new draft even if persistence fails; editor shows failure via saveDraft, never navigates away until it has rendered that draft. Names trim to 1–120 chars, default **Untitled recipe**, duplicates allowed. List sorts descending updatedAt then ID. ID/publishKey are distinct UUIDs.
- Storage uses **one item per new draft** `notebook:draft:v2:<id>`; no single mutable global draft index that drops sibling drafts on concurrent writes. Enumerate validated v2 keys for lists; one `setItem` atomically replaces each serialized draft. Same-tab saves dispatch `notebook:drafts-changed`; subscribe also listens to browser storage events. Debounced autosave 350 ms, flush on teardown, explicit named draft Rename/Discard/Resume. Different draft IDs never overwrite one another. For another tab updating the same draft, pause autosave and show **Changed in another tab**; require reload or Save as new draft. LocalStorage lacks CAS, so do not promise simultaneous-edit merge/conflict-free guarantees; retain in-memory copy and use fresh IDs for forks.
- On `/new` show **Start a new recipe** plus existing named drafts; neither recovery nor discard is prerequisite. Start creates a new draft and navigates to `/new?draft=<id>` with replaceState when assigning the initial editor identity to avoid misleading back history. Explicit draft URLs resume immediately; invalid/missing IDs show an error and Start new, never substitute another draft. Homepage resumes via draftHref. Empty untouched draft creation should occur only on Start/first content, not just opening the chooser.
- Idempotent migration reads old `notebook:draft:new` shape `{draft,revision?,key,undo?,saved}` and writes deterministic ID `legacy-new` in v2 (preserve publishKey from key, full draft/undo/exact prose and saved timestamp). Derive name from nonblank title or **Recovered recipe**. Remove old key only after successful serialization/write/readback of valid v2; if destination already exists, never overwrite it or delete a different old payload—surface it for explicit recovery as a new UUID draft. A failed/quota-limited/corrupt migration never destroys the source key. `notebook:draft:<recipeId>` edit drafts remain revision-bound, separate and compatible; do not publish them as new recipes accidentally. No database migration or server storage for local drafts.
- Successful recipe POST deletes **only** the corresponding v2 draft after receiving success, preserving its publishKey for ambiguous-response retries until then. Existing-edit success removes only its legacy edit key. 409/network/401/parse failure keeps exact draft, line inputs, undo and expected revision. Drafts/bookmarks remain device-local across name changes/logout; no server ownership claim arises from possession of their JSON.

### Shared foundations consumption

Sibling owns `src/ui/{Icon,Button,Modal,Dropdown,Tooltip,Spinner,TagPicker}.svelte`, primitive tests, `style.css`, frontend package/lock files. Do not edit or duplicate them. During design validation the sibling delivered TagPicker **under ui/** with this actual contract: `{tags:string[]; selected?:string[]; label?:string; placeholder?:string; single?:boolean; allowCreate?:boolean; onchange?:(tags:string[])=>void}`; selected is bindable, allowCreate defaults **true**. Browse must explicitly pass allowCreate=false; editor passes true and separately validates classifiers. Use tags/onchange, not invented options/onselect names. Current primitive uses locale comparison; consumers NFC-normalize known options and submitted selection, with backend casefold/dedup authoritative. ## 5. Acceptance/test plan

- **Backend identity/security:** anonymous GET session creates no user; organization succeeds without profile but POST/PUT recipe remains 401; forged owner/admin/profile fields never grant power; same-name profile cannot access original recipes. Origin/CSRF/size guards cover both parse APIs and lookup. Trusted-IP/global durable AI quota exhausts at exact configured limits with concurrent clients; missing/forged forwarded IP cannot avoid global budget. Revoked/blocked known identity cannot obtain a privileged parse bypass. Grants/revokes/block races against authorization fail closed inside transaction; revoked/expired credentials and old password cookies never admin. CLI list ordering/duplicates/cancellation/non-TTY/exact-ID/rollback audited grant/revoke. Pairing admin follows the user with explicit consent; privileged merge rejected on preview and execution including mid-flight grant.
- **Author/site copy persistence:** non-admin directory/settings/owner calls denied; eligible-owner filter before pagination; duplicate names selected by ID; pending photos/secrets absent.
